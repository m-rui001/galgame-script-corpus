# 英文语料的处理标准

`English/` 里的 137 个文件不是"待重写的译稿"，而是**已经出版的英文化**（NekoNyan、Sekai Project、JAST、MangaGamer 等）与少数机翻。这个区别决定了这里能做什么、不能做什么。

## 一、能做什么

**1. 修导出损伤。** 文本是从游戏引擎里抓出来的，抓取过程留下了这些东西：

- 引擎/HTML 标记：`{l[tobechecked10]}`、`<i>`、`[name]`、`\n` 字面量、`<br>`。功能性的保留；`{l[tobechecked…]}` 这类明显是导出器漏标的，删掉标记、保留正文。
- 标点：`....` → `…`；`!?` 与 `?!` 统一；`--` 与 `—` 统一；句号后缺空格（`word.Next`）补上；行尾多余空格删掉。
- 引号：同一文件内 `"` 与 `“”` 不要混用；按该文件的多数用法统一。
- 说话人标签：`Furukawa:` / `You:` / `Narration:` 这种前缀是导出器的产物，**保留**，只统一大小写与空格（`Name: text`）。不要发明新标签，不要删标签——标签是行级校验的依据。

**2. 把漏译的日文行译出来。** 有八个文件里成段落残留日文（`lang_scan.py` 会列出来：Sugar Style、Comyu、SaDistic BlooD、FLML、DRACU-RIOT、Senren Banka、Ley-Line Borderline、Maitetsu）。这些行**是翻译，不是润色**：

- 译成与上下文同风格的口语英语，不要照字面直译。
- 保留原有说话人标签与引号数。
- 不要顺手"改进"上一行已经译好的英文。

**3. 修真正的机翻腔。** 判据是"这句话不可能是英语母语者写的"，不是"我不喜欢这个说法"：

- 直译的日文语序：`The thing that I like is…`、`It is because… that…`、`As for me,…`
- 和制英语与生硬复合词：`one's own home`、`take a bath in`、`do a kiss`
- 冗余虚化：`the fact that`、`in regards to`、`it can be said that`、`there is no doubt that`
- 无主句堆叠、`somehow`/`various`/`certain` 滥用
- 拟声词直译：`Fuwa fuwa`、`Doki doki` 留在正文里而没有对应表达

改法是把句子重排成英语的自然语序，不是换同义词。

## 二、不能做什么

- **不重写已经通顺的段落。** 这是别人出版的译文。"我觉得这样更好"不是理由；只有能指出具体病灶（直译语序、漏译、标记残留、标点错乱）才动。
- **不改人物声口。** Makina 的 `ya know`、口语缩写、粗话是译者给人物定的调子，不要"规范化"。
- **不改剧情、事实、称谓、专名。** 人名拼写按该文件内的多数用法，不按外部资料统一。
- **不动功能性标记。** `<i>`、`{w}`、`\n`、`[name]`、变量占位符原样保留，数字集合与原文一致。
- **不做内容审查。** 成人向内容照原样，只做语言层面的修复。

## 三、切片作业的硬约束

一块 450 行里：

| 项 | 要求 |
|---|---|
| 说话人标签 | 出现两次以上的标签一个都不能丢；不新增 |
| 数字 | 多重集一致（含 `１９`、`3rd`、`Route A` 这类） |
| 引号 | `"`、`“”`、`'`、`‘’` 计数与源块一致 |
| 体量 | 词数 0.6–1.4 倍 |
| 新增非英文字符 | 不得新增日文假名；CJK 不得增加（漏译行译成英文时 CJK 会减少，正常） |
| 行数 | 可变：合并碎行、拆分长行都可以，但不要把两句台词并进一条标签 |

## 四、回报格式

每块给：改动行数占比、修了什么类别（标记/标点/漏译/机翻腔）、行数变化、以及**原样保留但确实有病的地方**（说明为什么不动）。
