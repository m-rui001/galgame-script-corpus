## 结构校验会拒绝的情形

润色合并只接受同时满足以下条件的行，否则保留原文：

- 行首说话人前缀一致（1–6 字，`名字：`）
- 引号 `「」『』` 计数一致
- 数字集合一致（阿拉伯数字不得改写为汉字）
- 中文行内无假名
- 内容长度 0.4–1.6 倍
- 分片行数与源区间完全一致（否则整片丢弃，防止错位）

## JA/ 的字形损坏（半角片假名可修，缺字不可修）

`tools/repair/fix_punct.py` 能修的：半角片假名 → 全角（全库 845 处，集中在 `Kao no nai Tsuki`、`ChronoClock`）。行首孤立标点 43 处、行尾空格若干。

修不了、只能记录的：Shift-JIS 转换留下的缺字与乱码块。例如 `ChronoClock`：

```
髞V内真琴です」        ← 前几个字被吃掉
潔t型はＡ型♪」         ← 同上
ﾈことないよー」        → ネことないよー」   （半角可转，缺的字补不回来）
```

这类位置**不要猜着补**：同一行上下的语境不足以确定原文，补出来等于编造。要修只能回原始游戏文件重新提取。全文扫描判据：

```python
re.search(r'[\u9ADF-\u9FFF]{1}[A-Za-z]', line)       # 汉字后紧跟单个拉丁字母
```

## 乽乿（已全部清除，2026-11-27）

乽 (U+4E7D) 与 乿 (U+4E7F) 不是引号，是 Shift-JIS→Unicode 转换事故的产物：
NEC 选 IBM 扩展区处理时，原文的 「/」 被映到了这两个字上。本语料库有 9 个文件
受影响，共 17,773 个 乽 与 17,747 个 乿（差值 26 即各文件里登记过的"缺收引号"
缺陷，转换后它们以缺失的 」 形式继续存在，不再是不可见的乱码）。

处理：全库 1:1 替换 乽→「、乿→」。替换不改变行数与行内其他内容，进度指针无需
