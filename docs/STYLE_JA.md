# 日文语料的处理标准

`JA/` 是日文原文，`Zh/` 的译本多从它们来。日文原本有两次可做的工：

1. **复原**（先做）：把导出过程弄坏的东西修回去——折行、半角假名、标点、缺字。
2. **润色**（后做，可选）：在地道日语的范围里把句子改好。这一条是项目所有者的明确要求：**润色不局限于译文，原文也要润色**。

顺序不能反。折行没合、假名还是半角、引号还缺着的时候去润色，等于在半坏的字上改文。

## 一、复原（`tools/repair/`）

**1. 固定宽度折行。** 导出器按屏幕宽度断行，一句被切两半：

```
花音「はぁ……私なんて、こんなにおヒゲがモジャモジャでも、
すぐに宮原くんだったらわかったのになぁ」
```

只在能确定是折行时合并：上一行没有句末标点（`。！？…─」』`），下一行不以说话人标签开头、不以开引号开头、不是纯汉字行接在假名行后面。工具 `fix_wrap.py` 还会先用候选行长度估出折行宽度：长度紧聚在某一列才是真折行，散开的（一句一行的诗体）整份文件跳过。已处理：`Ouchi ni Kaeru made`、`LOOPERS`、`Einstein`。

**2. 半角片假名。** `ｱｲｳｴｵ` `ｯ` `ｰ` `｢｣` 一律转全角（NFKC，只作用于半角范围）。已处理 845 处。

**3. 标点与空白。** 行首孤立的 `、。，`（折行残留）、行尾空格、`!?` 与 `?!` 按该文件主流写法统一（不跨文件强推）。

**4. 引号不配对。** `Salthe` 的成因值得记住：导出时台词被排序、行内换行被吃掉、句末 `」` 被删。所以不是"补收尾"，而是先算：

```
「5,213 / 」3,757        缺 1,456
行内被吃掉的 」          1,973
行首被吃掉的 「（以 」 开头的行）  517
1,973 - 517 = 1,456  ✓
```

算术闭合之后才动笔；补完要求"剥掉括号后与原文逐字节相同"。拿不准的（台词段与旁白段之间换行已丢、无法判定 `」` 落在哪个字后面）原样保留并报行号。

**5. 缺字与乱码块。** `ChronoClock` 里有 `髞V内真琴です」` 这类，字符被吃掉。**不要猜着补**——上下文不足以确定原文，补出来是编造。只记录行号，等从原始文件重新提取。

## 二、润色（原文也润）

复原做完之后，`JA/` 的段落按与中文同一套判据处理，只是落点是日语而不是中文：

- **句长起伏**：连续三句都是同一长度区间，就把中间一句压短或拉长。
- **句法轮换**：别句句「主语＋は＋述语」；状语前置、宾语前置、名词句收尾轮着用。
- **抽象落地**：`なんとなく`、`なんだか`、`〜という感じ`、`〜ような気がする` 这类虚化结尾，能换成具体的东西就换。
- **删冗词**：`〜ということ`、`〜という風に`、`〜的な`、`非常に`、`とても` 堆叠时删到只留一个。
- **收句落地**：段落最后一句要站住，不要以「……という感じ」「……ような気がする」悬着。

不动的：人名与称谓、汉字写法（`俺`/`僕`/`私` 的切换是人物设定）、方言、口头禅、拟声词、专名、成人向内容、剧情与事实。数字（全角/半角）原样。

## 三、`Bilingual/`：日中混排

有五个文件是原文与译文逐行交替的，单独放在 `Bilingual/`：

| 文件 | 中文行 | 日文行 |
|---|---:|---:|
| 毒舌クールな妹を性的に可愛がる！… | 47% | 53% |
| Mugen Kairou | 44% | 56% |
| 俺の恋天使がポンコツすぎてコワ～い。 | 41% | 59% |
| その恋、保留につき、ガーデンパーティー | 32% | 68% |
| 月は東に日は西に | 22% | 78% |

处理规则：

- **两边都润**：日文行按第二节，中文行按 `STYLE_ZH.md`；同一句的译法不要因为单边改写而与另一边脱节（术语、人名、称谓必须两边一致）。
- **不得丢假名**：一条日文行被换成纯中文，等于把原文删了，门禁会拒（`kana lost`）。
- **折行合并要克制**：这类文件里短暂的一行可能正是译文行，跨语言合行会把日文接到中文后面。工具遇到中日混排会整份跳过，需要人读。
- 判断某行属于哪种语言：有假名 → 日文；只有汉字且含 `的了这那们吗呢没吧啊` 之类的虚词 → 中文（`tools/lang_scan.py` 用的就是这个判据）。

## 四、切片作业的硬约束

| 项 | 要求 |
|---|---|
| 体量 | 0.6–1.4 倍（复原和润色都允许多几个词，短行另有绝对容差） |
| 数字 | 多重集一致（含全角） |
| 引号 | `「」『』（）` 计数一致，除非该块正在做引号修复 |
| 假名 | 不得减少（日文是原文，不是待替换的中间产物） |
| 行数 | 可减（合并折行），润色阶段也可变 |

## 五、回报格式

每块给：合并了多少处折行、半角假名修了多少、补了几处引号、体量变化、结构改动率，以及**原样保留的可疑位置**（行号 + 为什么不动）。

### 双语文件的作业方式：分语言两遍

这类文件里日文行与译文行交错，让模型"一把改两种语言"时，它会拿日文行去覆盖中文行，或者把两种语言合成一句。所以处理方式是**分语言两遍、另一语言用占位符封住**（`batch_api.py --two-pass`）：

1. 第一遍：中文行全部换成 `@@<行号>` 占位符，只让模型改日文行。行数必须 1:1，占位符必须逐字保留。
2. 第二遍：反过来，只改中文行。
3. 占位符对应的原文行由程序按位置还原——模型根本没机会碰它不该碰的行。

代价是这种模式下行数不能变（不能合行），收益是两种语言不可能互相覆盖。实测 `Mugen Kairou` 前 1,200 行，6 片里 5 片通过门禁，中文行的翻译腔确实被改掉了（「我在朦胧的意识中，听到了大小姐们的对话，在心中不停向她们道歉」→「意识模模糊糊，耳边飘进大小姐们的对话。我只能不停在心里道歉」）。

注意这类文件的行序本身是导出器排过的（日文行与中文行的相邻关系并不总是"原文＋译文"），所以不要试图"理顺"顺序。
